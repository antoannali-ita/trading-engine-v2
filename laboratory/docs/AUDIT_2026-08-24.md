# Trading Laboratory Audit — 2026-08-24

Scope: `strategy-lab-v1` plus the default-branch GitHub Actions launcher that schedules the Laboratory. Core trading logic and real-order paths are out of scope and were not modified.

## Fixed

### P1 — Paper position cap configuration drift

The declared Laboratory baseline is `MAX_POSITION_USD = 5_000`, while the default-branch scheduled launcher was explicitly setting `LAB_MAX_POSITION_USD=10000`. The paper job also had a local fallback of 10k when the environment variable was absent.

Correction applied:
- default-branch scheduled launcher now sets `LAB_MAX_POSITION_USD=5000`;
- branch scheduled/manual workflows now set `LAB_MAX_POSITION_USD=5000`;
- `run_paper_signals.py` now defaults to the declared `MAX_POSITION_USD` value instead of a duplicated hard-coded 10k fallback.

Classification: risk-configuration correction. It changes paper sizing relative to the accidentally deployed 10k value, but aligns execution with the already documented 5k baseline. No scoring, strategy, trigger, gate or backtest formula was changed.

Validation contract: `tests/test_configuration_contracts.py`, `tests/test_paper_job_guards.py`, plus the existing `test_risk_based_qty_respects_position_cap` test.

### P1 — Action Center policy mismatch

The Action Center stated that every `PAPER OPEN` required Strategy >=75, Trade >=75, Net R/R >=2.00 and a CONFIRMED trigger. That statement conflicts with the persisted Laboratory A/B/C research policy, where Tier B and Tier C intentionally have different admission rules and Tier C may admit a WAITING trigger as research-only.

The dashboard now labels 75/75, R/R 2.00 and CONFIRMED as **strict reference diagnostics**, displays the persisted paper tier and safety label, and shows Portfolio Gate as PASS/FAIL rather than an unavailable pseudo-score.

Classification: UI/diagnostic fix only. No paper admission rule changed.

### P1 — Open-position lifecycle coupled to LAB_SYMBOLS

Open paper positions were updated only while iterating the current candidate universe. Removing a ticker from `LAB_SYMBOLS` could therefore stop its daily stop/TP lifecycle checks.

The job now processes active-position symbols that are outside the configured universe in a lifecycle-only pass. Candidate generation remains restricted to configured symbols, so the fix does not expand the trade universe.

### P2 — Partial symbol failures reported as successful jobs

The paper job previously caught symbol-level failures, printed them and returned exit code 0. A scan could therefore be incomplete while GitHub Actions stayed green.

The job now aggregates candidate-scan and detached-lifecycle failures and returns non-zero when any occur. Failure to read active paper positions is treated as fatal because portfolio/lifecycle decisions would otherwise be made from incomplete state.

## Verified

- `lab_watchlist` is unique by `(symbol, strategy)` and active rows are loaded with `active=true`.
- `lab_paper_positions` has a partial unique index preventing two simultaneously active positions for the same `(symbol, strategy)`.
- `lab_signal_outcomes` is upserted by `(symbol, strategy, signal_date)`.
- D1/D3/D5/D10/D20/D60 and MFE/MAE are computed from post-signal daily bars and the outcomes job returns non-zero when row-level outcome persistence fails.
- Paper lifecycle uses conservative stop-first intrabar ordering and moves the stop to break-even after TP1.
- The actual scheduled Laboratory workflow lives on the default branch and checks out `strategy-lab-v1`; the branch copy alone is not sufficient for GitHub cron execution.
- The legacy daily workflow remains manual-only, avoiding duplicate scheduled Laboratory runs.

## Research changes required before baseline replacement

### R1 — Earnings date normalization

`earnings_distance_days()` currently returns negative values for stale/past Yahoo earnings dates. Existing gates interpret any value below the block threshold as an imminent earnings event. A stale date can therefore block a trade incorrectly.

Do not patch this directly into baseline. Candidate V2 should distinguish `past/stale`, `unknown`, and `future` earnings dates and be validated on recorded cases before replacing V1.

### R2 — Corporate actions / split-safe outcomes

Market data is downloaded with `auto_adjust=True`, while `entry_reference`, stop and targets are persisted at signal time. A later split can rescale historical adjusted bars without rescaling the stored reference values, corrupting D1-D60, MFE/MAE and R-multiples.

Candidate Outcomes V3 should persist or reconstruct an adjustment factor and prove parity on no-action names plus correct handling of known split cases before replacing the current outcome method.

### R3 — Watch threshold configuration drift

The default-branch scheduled launcher currently uses `LAB_WATCH_SCORE=50`, while branch/manual workflow copies still use 55. This changes which rows enter the Laboratory watch/funnel and therefore must not be normalized silently. Decide which value is the intended research baseline, version it, then validate before replacing the other configuration.
